================================================================
OPEN RUNTIME BUG (NOT BUILD-RELATED - do after green build)
================================================================
tweak/ChangeInfoIos.plist currently has:
  Mode = Any;
  Bundles = ( com.vng.zalo, ph.telegra.Telegraph, com.changeinfoios.app );
  Classes = ( UIDevice, UIScreen, CLLocationManager, ... 20 items );

Mode=Any + a broad Classes list means the dylib is STILL injected
into every UIKit process (including Sileo, apt-get, SpringBoard).
Previous hand-off (pre-redesign) documented this:
  - apt-get[20627] emitting "[ChangeInfoIos] Tweak loaded" logs
  - Sileo becoming unresponsive / "APT was unable to find this
    package" / "Unable to determine suitable packaging system type"
  - hooked_fork / hooked_getenv / hooked_dlopen in tweak/Hooks.mm
    are hostile when jbHideActive() returns true (default YES)

Fix direction (when build is green):
  1. Drop the Classes array entirely; keep only Bundles.
  2. In tweak/Tweak.xm flip jbHideActive() / fakeLayer() defaults
     so missing config = feature OFF.
  3. In tweak/Hooks.mm initCLvlHooks(), early-return for
     getprogname() in {Sileo, apt, apt-get, dpkg, SpringBoard,
     installd, lsd, assertiond, dasd, mobile_installation_d}.
