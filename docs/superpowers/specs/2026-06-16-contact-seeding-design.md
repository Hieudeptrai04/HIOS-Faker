# Contact Seeding Design

## Goal

After each successful Change Device flow, HIOS Faker should repopulate the real iOS Contacts database with a fresh, natural-looking set of contacts so apps such as Zalo can see non-empty address book suggestions.

The phone-number pool is provided by the user in `hA0E199i20bhyt.txt` and confirmed by the user as their data. The current file contains 5,052 unique numbers.

## Scope

The app will bundle the phone-number pool and, on each Change Device run:

1. Delete the previous contacts generated by HIOS.
2. Pick a random batch of 30 to 100 phone numbers from the bundled pool.
3. Normalize each number to a Vietnam E.164-style format, such as `+84397153576`.
4. Generate a random Vietnamese-looking full name for each contact.
5. Save the contacts into the real iOS Contacts database.
6. Store the generated contact identifiers so the next Change Device run deletes only HIOS-generated contacts.

The feature will not scrape or fetch phone numbers from the internet. It only uses the user-provided local pool.

## Architecture

Add a small contact-seeding module inside `app/main.m`, near the reset helpers:

- `CIContactsPoolPath()`: finds the bundled `contacts_pool.txt`.
- `ci_loadContactPool()`: parses whitespace-separated phone numbers and removes duplicates.
- `ci_normalizeVNPhone()`: converts local/VN-like phone formats to `+84...`.
- `ci_randomVietnameseName()`: creates natural-looking random names from built-in Vietnamese surname, middle-name, and given-name arrays.
- `ci_clearGeneratedContacts()`: deletes previously-created contacts by identifier.
- `ci_seedRandomContacts()`: clears old generated contacts, selects 30-100 pool entries, creates `CNMutableContact` records, and persists their identifiers.

Generated contact identifiers will be stored at:

`/var/jb/etc/changeinfoios/generated_contacts.plist`

Only identifiers from this file are deleted. Existing user contacts are never enumerated and deleted by phone number or name.

## Data Flow

The build will copy `hA0E199i20bhyt.txt` into the app bundle as `contacts_pool.txt`.

During `performRRSBackupLicensed`, after `ci_randomizeIdentities()` succeeds and before target apps are relaunched, the app will call `ci_seedRandomContacts()`. This timing gives Zalo a fresh address book before the next cold launch.

The home app already has platform/no-sandbox entitlements, but iOS Contacts access still needs:

- `Contacts.framework` linked in `app/Makefile`.
- `#import <Contacts/Contacts.h>` in `app/main.m`.
- `NSContactsUsageDescription` in `app/Resources/Info.plist`.

If Contacts permission is not available, the feature logs the failure and continues the Change Device flow without blocking the reset.

## Error Handling

Contact seeding is best-effort:

- Missing pool file: skip seeding and log.
- Empty/invalid pool: skip seeding and log.
- Contacts permission denied: skip seeding and log.
- Individual contact save failure: continue with the remaining contacts.

The reset flow should not fail solely because contacts could not be seeded.

## Verification

Manual verification:

1. Build/install the combined package.
2. Run Change Device.
3. Open Contacts and confirm 30-100 new HIOS-generated contacts exist.
4. Run Change Device again.
5. Confirm the old HIOS batch is gone and a new random batch exists.
6. Confirm personal contacts not created by HIOS remain untouched.

Static verification:

- Confirm `contacts_pool.txt` is present in the app bundle.
- Confirm `Contacts.framework` is linked.
- Confirm `generated_contacts.plist` stores the created identifiers.
