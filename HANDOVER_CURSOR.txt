2. ĐÃ LÀM QUA 6 VERSIONS (2.3.0 → 2.3.6)
================================================================

--- v2.3.1: Sandbox write fallback ---
Bug: Cocoa writeToFile: tới /var/mobile/Library/Preferences/com.changeinfoios.plist
     fail silent vì Sandbox block.
Fix: Thêm posix_spawn shell-copy fallback trong [CIConfigManager save].
     Copy từ /var/mobile/Library/Preferences/com.changeinfoios.app.plist
     sang com.changeinfoios.plist.
File: app/main.m — hàm ci_run + block trong save.

--- v2.3.2: HUD 5-state + completion summary ---
UI: HUD hiện 5 bước (backup → wipe → randomize → write → respring)
    + alert sau khi xong hiện Model/iOS/Serial/IDFA/UDID/IMEI.

--- v2.3.3: Respring fallback chain ---
Bug: killall SpringBoard fail rc=-1 (mobile user không có root).
Fix: Chain: sbreload → launchctl kickstart → killall SpringBoard.
File: app/main.m — trong performRRSBackup step 4/5.

--- v2.3.4: Auto-kill target apps ---
Bug: Target app (AIDA64) vẫn cache old values sau wipe.
Fix: Thêm block killApp chạy 3 method:
     killall -9 <ExecName>
     pkill -9 -f <bundleID>
     pkill -9 -f <bundlePath>
File: app/main.m — trong flow performRRSBackup.

--- v2.3.5: Filter plist XML + injection marker ---
Bug: ChangeInfoIos.plist ở format ASCII/OpenStep, nghi ellekit không parse.
Fix:
1) Convert sang XML plist đầy đủ <?xml ... ?> header.
2) Thêm Mode=Any, Executables fallback (AIDA64, Lirum, DeviceInfo...).
3) Trong Tweak.xm %ctor thêm marker file:
   /var/mobile/Library/Caches/ChangeInfoIos/injected_<bid>.txt
   → App check file này để biết tweak có inject thật không.

--- v2.3.6: FRAMEWORK LINK FIX (root cause chính, VỪA PUSH) ---
Bug phát hiện: Tweak.xm/Hooks.mm import WebKit, CoreTelephony, CoreLocation,
    CoreMotion, AdSupport, SystemConfiguration, Metal, AVFoundation, Security,
    AppSupport — NHƯNG Makefile trước đây CHỈ link UIKit + Foundation.
    → dylib load với unresolved ObjC class symbols
    → ellekit/substrate silently skip inject
    → DÙ FILE .dylib + .plist NẰM ĐÚNG CHỖ, HOOK VẪN KHÔNG CHẠY.

Fix (đã push commit 5343817):
tweak/Makefile:
  ChangeInfoIos_FRAMEWORKS = UIKit Foundation CoreFoundation CoreGraphics \
                             CoreTelephony CoreLocation CoreMotion \
                             AdSupport SystemConfiguration WebKit Metal \
                             AVFoundation Security
  ChangeInfoIos_PRIVATE_FRAMEWORKS = AppSupport

.github/workflows/build.yml:
  - ARCHS="arm64 arm64e"  (iPhone X là arm64e, trước chỉ build arm64)
  - Thêm step "Verify tweak dylib (arch + sign + link)" chạy:
      lipo -info <dylib>      (check 2 slice arm64+arm64e)
      ldid -e <dylib>         (check entitlements)
      otool -L <dylib>        (check framework links)
      nm -u <dylib>           (liệt kê undefined symbols)
      plutil -lint <plist>    (validate filter plist)
    → Nếu thiếu framework/arch → CI FAIL SỚM, không tốn công cài rồi test.

3. KIẾN TRÚC INJECT FLOW (QUAN TRỌNG HIỂU ĐÚNG)
================================================================

Luồng fake device info:
1) App UI (main.m) sinh random values → ghi /var/mobile/Library/Preferences/
   com.changeinfoios.plist (phải >5KB, ~142 keys).
2) App kill target apps (AIDA64/Zalo) → chúng sẽ restart.
3) App respring SpringBoard (sbreload ưu tiên).
4) Khi AIDA64 launch lại:
   a. ellekit/substrate đọc filter plist ChangeInfoIos.plist
   b. Match bundleID (com.finalwire.aida64...) → load ChangeInfoIos.dylib
   c. %ctor chạy → ghi injection marker + loadConfig() đọc shared prefs
   d. Hooks active: UIDevice.systemVersion, MGCopyAnswer(serial), v.v. return fake
5) AIDA64 call UIDevice → trả value fake, không phải thật.

Điểm chết (failure points):
- (1) fail → shared prefs 0 byte → hooks return %orig (v2.3.1 đã fix bằng shell copy)
- (4a) fail → filter plist sai format → substrate skip (v2.3.5 đã XML hóa)
- (4b) fail → framework link thiếu → dylib load fail → substrate skip (v2.3.6 đã fix)
