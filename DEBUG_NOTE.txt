# NOTE FOR CLAUDE DEBUGGING - ChangeInfoIos inject failure on AIDA64

## ISSUE SUMMARY

User's ChangeInfoIos tweak does NOT inject into AIDA64 (com.finalwire.aida64).
Symptom: After pressing "Change" in the app, the marker file
`/var/mobile/Library/Caches/ChangeInfoIos/injected_com.finalwire.aida64.txt`
does NOT appear.

Steps that work:
- Step 1 (View): Shows current fake data - works
- Step 2 (Change): Saves prefs to com.changeinfoios.plist - works (file is 8.4KB)
- Step 3 (Create folder): Folder is created
- After pressing Change, going back: marker file is MISSING

This means %ctor in the tweak dylib NEVER runs = dylib not loaded into AIDA64 process.

## WHAT WE KNOW

### Filter plist (on device)
Path: `/var/jb/Library/MobileSubstrate/DynamicLibraries/ChangeInfoIos.plist`
Current content (from device screenshot):
```
Filter {
  Bundles {
    finalwire.aida64              <-- MISSING "com." prefix
    com.finalwire.aida64-ios     <-- wrong bundle ID (doesn't exist)
    ...
    com.apple.mobilesafari
  }
  Executables {
    com.apple.mobilesafari       <-- ONLY has this one!
  }
  Mode Any
}
```

### Actual AIDA64 Info.plist (from device screenshot)
```
CFBundleIdentifier = com.finalwire.aida64
CFBundleExecutable = AIDA64_c3
```

### What we FIXED in source (just pushed)
1. Removed `com.finalwire.aida64-ios` from Bundles (doesn't exist)
2. Changed `AIDA64` to `AIDA64_c3` in Executables
3. Source file: `tweak/ChangeInfoIos.plist`

### %ctor code (Tweak.xm lines 1195-1254)
The %ctor does these in order:
1. Writes marker file `/var/mobile/Library/Caches/ChangeInfoIos/injected_<bundleID>.txt`
2. loadConfig() - reads com.changeinfoios.plist
3. ci_wipeContainerIfScheduled() - wipe app containers if scheduled
4. CFNotificationCenterAddObserver - Darwin notify
5. dlopen libMobileGestalt.dylib
6. MSHookFunction MGCopyAnswer, MGGetBoolAnswer, MGGetStringAnswer
7. dlopen IOKit.framework
8. MSHookFunction IORegistryEntryCreateCFProperty
9. initCLvlHooks() - from Hooks.mm
10. NSLog "Tweak loaded successfully!"

Marker file never appears = step 1 never runs = %ctor never executes.

## HYPOTHESES FOR WHY INJECT FAILS

### Hypothesis 1: Filter plist format issue
The device filter plist (from screenshot) shows:
- `finalwire.aida64` (missing "com.")
- `com.finalwire.aida64-ios` (wrong)
- `com.apple.mobilesafari` in Executables (wrong!)

This is VERY WRONG and shows the plist on device was likely NOT rebuilt from the fixed source.
The user needs to reinstall the deb from the NEW build (after the fix was pushed).

### Hypothesis 2: Mode=Any with missing executable
With `Mode=Any`, substrate injects if EITHER bundle OR executable matches.
BUT: if neither matches exactly (due to wrong names), no inject.
FIXED: Added AIDA64_c3 to Executables.

### Hypothesis 3: Substrate not installed properly
If ellekit/substrate is not installed in /jb/Library/MobileSubstrate/, dylibs won't auto-inject.

### Hypothesis 4: Code sign / entitlements issue
Dylib might be code-signed with wrong entitlements, causing kernel to reject loading.

### Hypothesis 5: dyld image blacklist
iOS might have dyld cache that blocks third-party dylibs from loading into certain apps.

### Step 2: Check filter plist AFTER reinstall

- `AIDA64_c3` in Executables (not just AIDA64)

### Step 3: Test with Safari (known working app)
Filter plist has `com.apple.mobilesafari`.
1. Open Safari on iPhone
2. Press Change in app (select Safari)
3. Check `/var/mobile/Library/Caches/ChangeInfoIos/injected_com.apple.mobilesafari.txt`

If this doesn't work either = substrate not working at all.

### Step 4: Check syslog for NSLog messages
```bash

log stream --predicate 'subsystem == "com.changeinfoios"' --level debug
# Or grep syslog
grep -i changeinfoios /var/log/syslog
```

The %ctor logs:
- `[ChangeInfoIos] Tweak loading...`
- `[ChangeInfoIos] MGCopyAnswer hooked` (or not found)
- `[ChangeInfoIos] Tweak loaded successfully!`

If NO logs appear = dylib never loaded.
If logs appear = %ctor runs but marker write fails.

### Step 5: Check dylib exists
